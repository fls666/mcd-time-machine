# 麦麦时光机 · McD Time Machine

> 把吃过的每一单，变成一份可分享的年度回忆、口味画像和消费趋势报告。

基于 **麦当劳中国 MCP（Model Context Protocol）开放能力** 开发的 Skill + CLI 工具：读取你的历史订单，
在本地完成统计与画像，输出一份终端简报 + Markdown 报告 + 完整 HTML 报告 + **V2.0 沉浸式年度故事页**（六章节滚动叙事 + 隐私友好竖版分享卡片）。

**零第三方依赖**（只用 Python 标准库）；**数据不出本机**，不上传、不外传。

## 为什么做这个

麦当劳 MCP 开放了历史订单、菜单、营养、优惠券、积分等 29 个 Tool，但普通用户很难直接消费这些数据。
「麦麦时光机」把它们串成一件有情绪价值的事：

- 记录里最早的那一单，是什么时候、点了什么
- 你是「嗜辣星人」还是「咖啡续命」，可信度多少、依据是什么
- 最豪华的一单，是哪一天、花了多少、点了什么
- 这一年的口味往哪个方向变了
- 哪些经典款你居然从来没吃过

## 快速开始

### 0. 环境要求

- Python **3.9+**（无需 pip 安装任何依赖）
- 一个麦当劳 MCP Token（[申请入口](https://open.mcd.cn/mcp)，手机号登录后点「控制台 → 激活」）

> 只想先看看效果？跳过 Token，直接跑 `mcdtm demo`，用虚构数据体验全流程。

### 1. 安装

```bash
git clone https://github.com/fls666/mcd-time-machine.git
cd mcd-time-machine
pip install -e .          # 或者直接用 python -m mcd_timemachine，无需安装
```

### 2. 配置 Token（请用环境变量）

```bash
export MCD_MCP_TOKEN="你的MCP Token"      # Windows PowerShell: $env:MCD_MCP_TOKEN="..."
```

> **不要用 `--token` 传密钥**：命令行参数会留在 shell 历史里，并可能被同机其他进程看到。
> `--token` 仅为临时调试保留。

### 3. 先诊断，再采集

```bash
mcdtm doctor      # 检查连通性、打印 order-list 的真实入参 schema 与返回结构
mcdtm tools       # 列出当前账号可用的 MCP 工具
mcdtm all         # 拉取（自动翻页）+ 分析 + 生成报告
```

没有 Token 也能玩：

```bash
mcdtm demo --count 160
```

**Windows 用户**：看 [docs/WINDOWS_SETUP.md](./docs/WINDOWS_SETUP.md)，
从装 Python 到配环境变量到排障，每一步都有截图级说明；
也可以直接跑 `python scripts\windows_wizard.py` 走一键向导。

## 命令一览

| 命令 | 作用 |
| --- | --- |
| `mcdtm demo` | 用**虚构**示例数据跑通全流程，用于演示与自测 |
| `mcdtm doctor` | 诊断真实 MCP：连通性、工具 schema、首屏返回结构（结果写入 `doctor.json`） |
| `mcdtm tools` | 列出麦当劳 MCP 当前开放的工具，`*` 标记本工具会用到的 |
| `mcdtm fetch` | 拉取历史订单（**自动翻页**）与菜单、营养、优惠券等增强数据 |
| `mcdtm analyze` | 基于已拉取数据做分析并生成报告 |
| `mcdtm story` | 用已有 `profile.json` 重新生成沉浸式故事页 `story.html`（不联网、不重算） |
| `mcdtm all` | `fetch` + `analyze` |
| `mcdtm inspect orders` | 打印某个工具的原始返回，便于核对字段结构（**含隐私，勿公开**） |
| `mcdtm share` | 导出**脱敏**后的结构报告 `share.json`，供排障求助（公开前仍需人工过目） |

通用参数（写在子命令前后都可以）：`--token` / `--endpoint`（默认 `https://mcp.mcd.cn`）/ `--out`（默认 `./mcdtm-output`）
/ `--privacy`（`personal` 默认，`public` 为公开分享版）。
`fetch` 另有 `--max-pages`（默认 30）与 `--page-size`（默认 100）。

## 数据可信度：报告会如实说明自己

一个看起来漂亮、但统计可能不完整的年度报告，会损害作品的可信度。
所以每份报告**开头固定有一块「数据说明」**，明确列出：

| 项目 | 说明 |
| --- | --- |
| 数据来源 | 「真实数据 · 来自麦当劳 MCP」或「示例数据 · 虚构生成」，用彩色徽章区分 |
| 统计区间 | 实际覆盖的首尾日期 |
| 订单覆盖 | 最终统计 N 单，原始拉取 M 条，去重 X 条，翻了 P 页 |
| 字段完整度 | 有日期 / 有金额 / 有明细 各是多少单 |
| 覆盖范围告警 | 若达到分页上限，会明确写「可能仍有订单未纳入统计」 |
| 工具状态表 | 每个 MCP Tool 是成功还是被跳过 |

同时：
- **金额分口径统计**：「实际支付金额」与「按单价×数量估算的商品金额」分开计算。
  有实付金额时主指标只认实付；含估算值时明确标注「N 单为估算值」，
  并说明估算未包含优惠券、配送费与退款
- **指标标题随口径变化**：只有部分订单有实付金额时，卡片标题会变成「已记录实付金额」
  并附「金额覆盖 X/Y 单（Z%）」，不会被误读成全部订单的真实支出
- **样本量保护**：低于 5 单或 8 件单品不做任何偏好判定，直接给「口味探索中」；
  达到门槛后仍会按样本量对可信度打折（最低 6 折），并要求最小支撑量
- 若存在缺金额的订单，报告会直接提示「累计消费可能低于实际值」
- 示例数据报告顶部有橙色横幅，写明「不来自任何真实账号」
- 所有统计口径（去重规则、翻页规则）都在 [`MCP_INTEGRATION.md`](./MCP_INTEGRATION.md) 中说明

## 它算出了什么

| 维度 | 内容 |
| --- | --- |
| 数据说明 | 来源、区间、覆盖、字段完整度、告警、工具状态 |
| 数字总览 | 订单总数、累计消费（分实付 / 估算口径）、平均客单价、单品总数、月均消费、最长连续打卡 |
| 年度关键词 | 年度单品、品类控、时段档、口味标签、黄金搭档、主场门店 |
| 口味画像 | 每个标签附 **0–100 可信度**（高 / 中 / 低）、可核对的**数据依据**与样本量；样本不足（<5 单或 <8 件）直接给「口味探索中」，不硬凑标签 |
| 口味变化 | 前后半程各品类占比的变化，给出上升 / 下降的百分点；**按订单序号对半分组**并注明分组区间，避免同一天大量订单导致失衡 |
| 品类偏好 | 汉堡、小食、甜品、饮料、早餐、沙拉 的件数与占比 |
| 消费趋势 | 逐月订单数与消费额 |
| 时间切片 | 七个时段分布、一周七天节奏 |
| 年度回忆 | 记录中的第一单、最豪华的一单、最豪横的一次、最常光顾的月份、你的主场、深夜食堂、最长连续打卡 |
| 黄金搭档 | 同单共现次数最高的组合 |
| 下次试试 | 结合品类偏好、复购频率、近期偏好与口味趋势推荐**还没点过**的单品；商品名会先做标准化（规格 / 别名 / 套餐），同品类最多 2 个以保证多样性（命中营养 Tool 时附带热量） |

## V2.0 沉浸式年度故事页（`story.html`）

除了完整报告，每次分析还会产出一份面向手机竖屏的**六章节滚动故事**：

| 章节 | 内容 |
| --- | --- |
| 1 时光机启动 | 年度标题、统计区间、订单 / 单品 / 跨度 / 连续打卡四个数字、来源徽章、「进入故事」按钮 |
| 2 故事的起点 | 最早的一单 + 年度回忆时间轴 |
| 3 我的麦麦日常 | 消费节奏、出没时段、一周节奏、品类偏好、常点单品、黄金搭档 |
| 4 口味人格测试结果 | 口味标签 + 可信度进度条 + 数据依据 + 样本量说明 |
| 5 这一年的变化 | 前后半程口味对比（含分组依据）、月度订单趋势、趣味记录 |
| 6 年度终章 | 年度关键词、下次试试、分享卡片生成器、数据说明 |

体验与工程上的取舍：

- **动画只是增强**：章节正文由 Python 直接渲染进 HTML，JS 只负责渐显。
  禁用 JS、JS 报错、或浏览器缺少 `IntersectionObserver` 时，六章内容依然完整可读；
  系统开启「减少动态效果」（`prefers-reduced-motion`）时不做任何位移与渐变。
- **移动端优先**：`svh` 高度兼容 iOS 地址栏收缩、底部安全区留白、
  中文长串与长商品名用 `overflow-wrap: anywhere` 防止横向溢出。
- **离线单文件**：CSS / JS / 数据全部内联，不请求任何网络资源，双击即开。
- **模板与代码分离**：`assets/story.html`（骨架）、`assets/story.css`、`assets/story.js`
  由 `mcd_timemachine/story.py` 注入数据组装，不再把 HTML / CSS / JS 堆在 `reporter.py` 里。

### 隐私友好分享卡片

第 6 章可生成 **1080 × 1920 竖版 PNG**（`share-card.png`），适配常见手机分享场景：

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| 消费金额 | **隐藏** | 勾选后才写入图片，未勾选画面显示「已隐藏」 |
| 门店名称 | **隐藏** | 同上 |
| 消费日期 | **隐藏** | 同上 |
| 生成时间 | **隐藏** | 同上；不勾选时页脚也不会出现具体时刻 |

- 卡片由本机 Canvas 绘制并导出，**不含位置、账号等元数据**（导出的 PNG 里没有 `tEXt` / `iTXt` / `tIME` 等块）；
- 未勾选的字段不会进入绘制文本，也不会写进「复制卡片配置」；
- 单行文字都有**最大绘制宽度 + 省略号截断**：商品名、门店名再长也不会顶出画布或压到相邻文字；
- 版式是**自上而下一次性分配高度预算**：关键词先排版拿到真实行数，人格描述的行数按剩余空间自动裁剪，
  面板高度随之自适应；人格名、关键词、字段面板之间不会压叠，字段面板也不会越过页脚。
  极端超长文本下宁可少画一行描述，也不会把文字画到面板外面。

### 两种生成模式：个人完整版 / 公开分享版

「隐私浏览」开关只是**前端遮挡**，文件里仍有原始数据。要真正安全地分享，用生成期的脱敏模式：

```bash
mcdtm demo  --out mcdtm-output                  # 默认 personal：个人完整版（含原始数据）
mcdtm story --out mcdtm-output --privacy public # 公开分享版：敏感值在生成时就不写入文件
```

| 模式 | 金额 | 门店名称 | 日期 | 分享卡片字段 | 页面提示 |
| --- | --- | --- | --- | --- | --- |
| `personal`（默认） | 保留，页面可临时遮挡 | 保留 | 保留到日 | 四项可勾选（默认隐藏） | 顶部黄条：本文件含原始数据，请勿直接转发 |
| `public` | **不写入文件** | **不写入文件** | 只保留「年-月」 | 四项置灰、无可展示内容 | 顶部绿条：已移除，且提示同目录其它文件仍是完整的 |

- 公开版是**生成期脱敏**：不是 CSS 遮挡，`story.html` 里连一个 `¥`、一个 `2026-06-27` 形式的日期、
  一个门店名都找不到（有单元测试与浏览器测试双重断言）；
- 保留「年-月」粒度是因为第 5 章的月度趋势与口味变化分组依赖月份，页面与文档都写明了这一点；
- `report.md` / `report.html` / `profile.json` **始终是完整报告**，不受该参数影响 ——
  公开版页面上与页脚都会提醒不要把这些文件一起发出去。

## 设计要点

**1. 真分页，不是「只取第一页」**
先探测服务端接受的分页参数命名（7 种组合），再循环翻页，直到本页不满、全是重复订单或命中终止信号；
达到 `--max-pages` 上限时会在报告里明确标注「可能不完整」。

**2. 可靠去重**
以**完整订单号**为唯一键；无订单号时退化为整条记录的 SHA-256 全量哈希，不再用「JSON 前 200 字符」这种会误判的近似标识。

**3. 防字段误判**
抽取整单金额 / 时间时只在订单本体与浅层结构中查找，并显式跳过 `items` / `products` 等明细容器，
避免把某个单品的价格或时间当成整单数据（有专门的回归测试守着）。

**4. 不假设返回体结构**
麦当劳 MCP 各 Tool 的字段命名不统一且会随版本演进，因此用「候选字段名 + 有限深度搜索」做兼容解析；
解析不出时保留原始 JSON，`mcdtm inspect` / `mcdtm doctor` 可随时核对。

**5. 隐私优先**
- 所有数据只写入本地 `mcdtm-output/`，无任何外发请求（除 MCP 官方接口）
- 仓库配置示例只含 `${MCD_MCP_TOKEN}` 占位符
- `.gitignore` 已排除 `mcdtm-output/`、`.env` 等一切可能含敏感信息的文件
- **请勿把 `mcdtm-output/raw/` 下的原始返回（含订单、门店等个人信息）提交到任何公开仓库或发给他人**
- 分享场景分两档：页面上的「隐私浏览」只是**临时遮挡**；要真正脱敏请用
  `mcdtm story --privacy public`，金额 / 门店名 / 到日日期在生成期就不会写进文件

**6. 零依赖**
只依赖 Python 标准库，`git clone` 下来就能跑。
前端验收用的 jsdom / Playwright 仅用于测试，不影响运行期（也未被 import 进任何运行路径）。

## 常见问题

**Q：为什么 `mcdtm fetch` 解析出 0 条订单？**
A：先跑 `mcdtm doctor`，再跑 `mcdtm share`，把生成的 `share.json`（已脱敏）贴到 Issue。
  > 脱敏只保留字段名与值的类型，并会扫描手机号/邮箱/身份证/URL/长串凭证，
  > 但**无法保证覆盖所有未知字段**，分享前请自己通读一遍。
我据此补齐 `collector.py` 里的 `K_*` 字段候选表，通常一次就能修好。也欢迎直接 PR。

**Q：会漏掉订单吗？**
A：会翻页直到取不到新数据。若订单量极大且达到 `--max-pages` 上限，报告「数据说明」会明确标注不完整——不会默默少算。

**Q：提示 401 / 429？**
A：401 是 Token 无效或过期，去控制台重新激活；429 是触发 600 次/分钟限流，客户端已内置指数退避重试。

**Q：营养热量没显示？**
A：只有账号能调到 `list-nutrition-foods` 且餐品能对上名时才展示，属增强项，不影响主流程。
