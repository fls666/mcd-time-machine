# 真机走查清单（iOS Safari / Android Chrome）

代码侧的移动端适配已经就绪，但**无头 Chromium 用的是 Linux 字体度量**，
真机的中文字体（iOS 用 PingFang SC、Android 用思源/系统字体）宽度不同，
所以下面这些必须用真机过一遍。

> 清单对应的页面：`docs/preview-story.html`（个人完整版）与
> `docs/preview-story-public.html`（公开分享版）。
> 两者都是**单文件、离线可打开**，不含任何真实账号数据（示例数据由程序生成）。

## 一、先把页面放到手机上（三种方式，挑一种）

**A. 直接传文件（最省事，不需要电脑开着）**

把 `docs/preview-story.html` 通过微信文件传输助手 / AirDrop / 网盘发到手机，
用 Safari 或 Chrome 打开即可。单文件内联了 CSS / JS / 数据，**断网也能看**。

**B. 局域网静态服务（推荐，能顺便测「导出 PNG」的真实下载行为）**

`file://` 协议在 iOS 上限制较多，想验证导出与剪贴板就用这种方式：

```bash
# 1) 查本机局域网 IP
#    Windows：ipconfig（找「IPv4 地址」）/ PowerShell：Get-NetIPAddress -AddressFamily IPv4
#    macOS/Linux：ifconfig | grep "inet "  /  ip -4 addr

# 2) 在仓库根目录起一个静态服务，只绑到局域网网卡（不要用 0.0.0.0）
python -m http.server 8123 --bind <电脑局域网IP>
```

手机与电脑连同一个 Wi-Fi，浏览器打开：

```
http://<电脑局域网IP>:8123/docs/preview-story.html
http://<电脑局域网IP>:8123/docs/preview-story-public.html
```

注意：这会把 `docs/` 目录临时暴露在同一局域网内。该目录只有示例数据生成的成品，
没有真实订单（真实数据在 `mcdtm-output/`，不在 `docs/`）；用完 `Ctrl+C` 停掉即可。

**C. 合并进 `main` 后用 GitHub Pages**：最接近评委看到的形态，但需要先合并 PR。

## 二、逐项走查（打勾用）

### 首屏
- [ ] 标题、四个关键数字、来源徽章、按钮都完整可见，没有被地址栏裁掉
- [ ] 上下滑动时地址栏收缩/展开，首屏高度跟着变但内容不被裁切
      （对应实现：`min-height: 100vh` + `@supports (min-height: 100svh)` 渐进增强）
- [ ] 底部内容没有被 Home 指示条 / 手势条压住
      （对应实现：`env(safe-area-inset-bottom)` + `viewport-fit=cover`）

### 六章滚动叙事
- [ ] 滚动时各章卡片依次渐显；顶部进度条随滚动增长
- [ ] 右侧章节圆点跟随当前章高亮，点圆点能跳章
- [ ] 系统开启「减少动态效果」后内容仍然完整可读（不做渐显）
- [ ] 关掉 JS（或用无痕+禁用脚本的浏览器）后六章内容依然完整

### 图表
- [ ] 条形图有实际宽度（不是空条）
- [ ] 月度趋势图柱子高低正确，横向可滑动，长按/悬停能看到「年-月：N 单」

### 隐私浏览开关（仅个人版可见）
- [ ] 打开后正文里的金额与到日日期就地变成「已隐藏」
- [ ] 再点一次能恢复；按钮文案在「开（已打码）/关」之间切换
- [ ] 公开版页面上这个开关不显示（CSS 已隐藏）

### 第 6 章 · 分享卡片（最需要真机确认的部分）
- [ ] 初始四项都是「已隐藏」，卡片页脚**不出现**具体生成时刻
- [ ] 逐个勾选，卡片实时重绘；每勾一项，对应行的值才从「已隐藏」变成真实值
- [ ] 只勾前三项时，页脚**仍然**没有「生成于 …」；勾上「生成时间」才出现
- [ ] **文字没有贴边、没有互相压叠、没有超出卡片左右边界**
      （这是重点：超长商品名 / 门店名 / Emoji 都该以「…」收尾）
- [ ] 点「导出 share-card.png」：
      - 若直接下载 → 到「文件」App 里确认存在
      - 若变成新标签页打开图片 → **长按图片「存储到照片」也算通过**，
        请顺手记下机型与系统版本（iOS 对 `<a download>` 的支持随版本不同）
- [ ] 导出的图在相册里查看：1080×1920、「…」截断正常、没有方框乱码（Emoji）
- [ ] 点「复制卡片配置」→ 粘贴到备忘录：未勾选的字段必须是「已隐藏」，
      且末尾有 `导出配置：{"amount":…,"store":…,"date":…,"generated":…}` 一行

### 其它
- [ ] 横竖屏切换后布局正常（卡片预览不溢出、文字不重叠）
- [ ] 页面不发起任何外部请求（离线打开也完全正常）
- [ ] 公开版：页面文字里搜不到 `¥`、搜不到 `2026-06-27` 形式的日期、搜不到门店名；
      四项开关是**置灰**状态且写「公开版未写入」
- [ ] 公开版页脚与横幅都提示了「同目录的 report.html / report.md / profile.json 仍是完整数据」

## 三、已经由自动化覆盖、真机只需抽查的部分

以下已在 Chromium（375×812、deviceScaleFactor 3）里逐条断言过，真机抽查即可，
不需要逐项复验：横向溢出、36 个渐显元素逐个滚动显现、长文本与极端字符抗溢出、
面板几何边界（描述没跑出人格面板 / 胶囊没压到字段面板 / 字段面板没越过页脚）、
PNG 尺寸与「不含元数据块」、极端字符下 Emoji 不被劈成孤立代理对。

真机特有的差异只有一处需要重点看：**字体度量不同导致的文字宽度差异**
（已实现为运行时 `measureText` 自适应截断，理论上安全，肉眼确认即可）。

## 四、发现问题怎么反馈

记下 **机型 + 系统版本 + 浏览器**，附截图（卡片问题可直接附导出的 PNG）。
不要附 `mcdtm-output/doctor.json`、`raw/`、`orders.normalized.json`——那些含真实订单数据。
